# Nazgob Personal — Mounted Combat

Целевая среда: Foundry VTT **13.351**, D&D5e **5.2.5**, Midi-QOL v13.

Для автоматического изменения геометрии аур поддерживается **Aura Effects 1.5.2** — ветка для Foundry V13. Если Aura Effects выключен, вся остальная верховая автоматизация продолжает работать, но ауры остаются обычными.

## Предмет

Создай у персонажа особенность с названием:

```text
Сесть на скакуна
```

У особенности должна быть обычная Activity, которую можно использовать. Модуль перехватывает её использование сам — отдельный макрос предмету не нужен.

После посадки предмет автоматически переименовывается в `Спешиться со скакуна` и обратно при спешивании.

## Настройка скакунов и изображений

Вся пользовательская настройка теперь находится **в описании самой особенности**. Никакие UUID или пути к изображениям в JS и на Actor больше не настраиваются.

Для каждого разрешённого скакуна укажи две строки подряд:

```text
@UUID[Actor.F4SsuskhKj3OA2f2]{Болотник / Moorbounder}
mountedTexture: worlds/ИМЯ-МИРА/assets/mounts/moorbounder-mounted.webp
```

Первая строка определяет Actor скакуна. Вторая — изображение его токена со всадником.

Если скакунов несколько, просто повтори пару строк:

```text
@UUID[Actor.F4SsuskhKj3OA2f2]{Болотник / Moorbounder}
mountedTexture: worlds/ИМЯ-МИРА/assets/mounts/moorbounder-mounted.webp

@UUID[Actor.ABC123]{Боевой конь}
mountedTexture: worlds/ИМЯ-МИРА/assets/mounts/warhorse-mounted.webp
```

`mountedTexture` относится к ближайшей `@UUID[Actor....]` строке **над ним**. Путь можно брать из любого доступного Foundry хранилища файлов.

Прозрачная текстура всадника уже входит в модуль: `assets/transparent.png`.

Если меняешь `MODULE_ID`, обязательно одновременно измени `id` в `module.json` и имя папки модуля.

## Использование

1. Включи модуль и Midi-QOL.
2. Перезагрузи мир.
3. Выбери токен всадника.
4. Возьми разрешённого скакуна в Target.
5. Используй Activity особенности `Сесть на скакуна`.
6. Для спешивания снова используй ту же особенность — она уже будет называться `Спешиться со скакуна`.


## Медальон затягивающихся ран

Если у Actor экипирован предмет с точным названием `Медальон затягивающихся ран`, модуль обрабатывает штатный бросок Кости хитов через hooks D&D5e.

- расход Кости хитов остаётся штатным;
- чат-карта и штатный Hit Die workflow не заменяются;
- `flags.midi-qol.grants.max.damage.heal = true` дополнительно поддерживается для **Костей хитов**: перед вычислением броска каждая DiceTerm получает минимум, равный числу её граней (`d10 → d10min10`, `d4 → d4min4`);
- фиксированные бонусы при максимизации не меняются: `1d10 + 3 → 10 + 3`;
- если экипирован медальон, затем удваивается **весь итог броска Кости хитов**, включая модификатор Телосложения и другие модификаторы, уже вошедшие в итог;
- лечение не может поднять текущие HP выше `effectiveMax`.

Пример для `1d10 + 3`:

```text
Обычный результат 4+3 = 7                 → 7 HP
Только медальон                           → 14 HP
Только max.damage.heal: 10+3 = 13         → 13 HP
Оба эффекта: (10+3) × 2                   → 26 HP
```

### Max-heal и верховая пара

Midi-QOL штатно проверяет `flags.midi-qol.grants.max.damage.heal` только по первой цели общего healing roll. Для активной верховой пары модуль исправляет смешанный случай, когда одновременно лечатся всадник и скакун, но max-heal есть только у одного из них.

Например, если `1d4` выпало `2`, а max-heal есть только у всадника:

```text
Только всадник → 4 HP общего пула
Только скакун  → 2 HP общего пула
Оба сразу      → 4 + 2 = 6 HP общего пула
```

Порядок выбора всадника и скакуна не влияет на результат.

Начиная с `v0.1.9`, служебные Midi-QOL hooks этой механики не возвращают `false`: это важно, потому что `midi-qol.preDamageRoll` трактует `false` как прямой запрет броска урона/лечения.

Начиная с `v0.1.10`, для Midi-QOL v13 итог обычного общего healing roll захватывается на актуальном hook `midi-qol.DamageRollComplete`. Модуль также временно переставляет немаксимизируемую цель первой и в `workflow.targets`, и в `workflow.hitTargets`, потому что Midi-QOL проверяет `hitTargets.first()` раньше `targets.first()`. После формирования броска исходный порядок обоих наборов восстанавливается.

## Стабилизация teardown пары (v0.1.11)

Спешивание теперь начинается с атомарного барьера `tearingDown`: отложенные movement/Midi callbacks не могут снова записать общий пул, передвинуть всадника или восстановить flags уже разбираемой пары.

При загрузке сцены модуль больше не «достраивает» половинчатую пару. Если связь осталась только с одной стороны, сохранён `tearingDown`, либо предмет уже называется `Сесть на скакуна` при оставшихся flags пары, состояние считается остатком прерванного спешивания и автоматически очищается с восстановлением текстур/`sort` и разделением общего пула, если он ещё активен.

## Ограничения первой версии

- всадник: токен 1x1;
- скакун: токен 2x2;
- Midi-QOL обязателен;
- изменение размеров/превращение токенов во время активной пары не поддерживается;
- `Угроза малым` применяется только к `mwak`;
- «верхом» для проверки цели считаются только пары, созданные этой автоматизацией.

## Досягаемость и ауры верхом

Пока персонаж физически остаётся верхом, независимо от активности общего пула хитов:

- все его рукопашные атаки `mwak` и `msak` проверяют досягаемость также от полного 2x2 footprint скакуна через штатный `rangeOverride.attack` Midi-QOL;
- его собственный токен остаётся 1x1 и отдельной целью;
- ауры Aura Effects 1.5.2 остаются эффектами Actor всадника, но дальность рассчитывается от полного 2x2 footprint скакуна;
- при спешивании и досягаемость, и геометрия аур возвращаются к обычному токену всадника.

Для досягаемости используется штатный `rangeOverride.attack` Midi-QOL. Для Aura Effects модуль использует его собственные функции расчёта дистанции и применения/снятия дочерних эффектов; размер токена всадника физически не меняется.

7. Массовое лечение.

9. Спешивание.
