# Nazgob Personal

Целевая среда: Foundry VTT **13.351**, D&D5e **5.2.5**, Midi-QOL **13.0.61**, DAE **13.0.27**.

Для автоматического изменения геометрии аур поддерживается **Aura Effects 1.5.2** — ветка для Foundry V13. Если Aura Effects выключен, остальная автоматизация работает, ауры остаются обычными. Для анимаций огнестрела нужен **Sequencer** (и JB2A для стандартных файлов).

## Функции

В начале настроек модуля — флажки «Функция: …». Каждый обработчик проверяет свой флажок при срабатывании, поэтому после переключения перезагружать мир не нужно.

| Флажок | Что делает | Зависит от |
|---|---|---|
| «Одно целое» | общие хиты наездника и скакуна, посадка, изображение пары | — |
| Досягаемость от скакуна | рукопашные атаки верхом считают дальность от токена скакуна | «Одно целое» |
| «Угроза малым» | преимущество верхом против цели меньше скакуна | «Одно целое» |
| Ауры верхом | ауры наездника считаются от токена скакуна | «Одно целое», Aura Effects |
| Верховое оружие | «Верховой бой» и «Наскок» | «Одно целое» — только для «Верхового боя» |
| Медальон затягивающихся ран | удвоенное лечение Костями хитов | — |
| Max-heal для Костей хитов | грант Midi max-heal максимизирует Кости хитов | — |
| Max-heal при лечении пары | общее лечение пары, когда max-heal только у одного | «Одно целое» |
| Анимации огнестрела | выстрел, попадание, звук | Sequencer |

Выключение «Одного целого» не разрывает пару: хиты перестают синхронизироваться, картинка наездника снова видна. При включении ГМ пересчитывает пул по последнему сохранённому значению, как после перезагрузки. Эффект досягаемости снимается сразу при выключении любой из двух функций.

Консоль: `game.modules.get("nazgob-personal").api` (то же, что `NazgobMountedCombat`) — `isFeatureEnabled(id)`, `oneWhole`, `firearms`.

## «Одно целое»

> Когда вы садитесь на скакуна, то можете объединить ваши хиты, сложив текущие хиты скакуна и свои. Если ваши общие хиты опущены до 0, вы оба начинаете умирать. Если вы оба попадаете в область эффекта, вы совершаете независимые спасброски, а из общего пула вычитается больший урон один раз. При спешивании скакун сначала восстанавливает хиты, которые были у него перед посадкой, остаток становится вашими хитами.

### Настройки

В настройках модуля:

| Настройка | Значение |
|---|---|
| UUID наездника | `Actor.mOmeXQtCSMIDWYYl` |
| UUID скакуна | `Actor.F4SsuskhKj3OA2f2` |
| Изображение пары | путь к картинке скакуна с наездником |
| Масштаб изображения пары | по умолчанию `1` |

У обоих Actor должна быть включена привязка токена к актёру (linked token). Перед сменой UUID спешьте наездника.

### Посадка и спешивание

- **Посадка.** Перетащите токен наездника на токен скакуна и ответьте «Да» на вопрос «Объединить наездника и скакуна?».
- **Спешивание.** Любое перемещение токена наездника, пока пара объединена, сначала спрашивает «Разъединить наездника и скакуна?»:
  - «Да» — пара разделяется, и наездник переносится, куда его тащили;
  - «Нет» — перемещение отменяется.
- Если выделить и сдвинуть наездника и скакуна одним действием, вопроса нет: это движение пары.

Пока пара объединена:

- токен скакуна получает изображение пары, исходное изображение хранится во флаге токена и возвращается при спешивании;
- **на сцене** скрывается только картинка наездника. Его полоски, значки эффектов, рамка и прицел видны, в чате и карточках изображение прежнее;
- токен наездника стоит в той же клетке, что и левый верхний угол скакуна, поверх него. Его можно выделить и взять в цель отдельно;
- перемещение скакуна ведёт наездника тем же путём.

### Общие хиты

- При объединении каждое существо получает к временному максимуму хитов (`tempmax`) бонус, равный собственному максимуму партнёра (`hp.max` + его `tempmax`, без бонуса «Одного целого»). Поэтому общий максимум у обоих одинаковый и равен сумме их собственных максимумов. Эффект «Одно целое — общий максимум хитов» имеет фиксированный ID, поэтому дубли невозможны.
- Текущие хиты обоих становятся суммой их текущих хитов, временные хиты тоже складываются и дальше синхронизируются.
- **Урон по одному существу** получают оба. Он считается и с модификаторами цели, и с сопротивлениями, уязвимостями и иммунитетами партнёра; из пула вычитается больший.
- **Урон по обоим из одного источника**, например Огненный шар, учитывает независимые спасброски и модификаторы каждого; из пула вычитается больший один раз.
- Лечение каждого из них лечит пул, лечение обоих складывается, но не выше общего максимума.
- Временные хиты общие: урон снимает их первыми, новые заменяют текущие, только если их больше.
- Хиты на 0 — оба на 0 и оба начинают умирать по обычным правилам системы.
- Изменение максимума партнёра (уровень, Телосложение, эффекты) пересчитывает бонус автоматически.

«Одновременно» — это урон из одной workflow Midi-QOL; для урона не из Midi (кнопки чат-карты dnd5e, ручная правка листа) — изменения в пределах 0,2 с.

### Связь между сценами

Состояние пары хранится одним флагом на Actor наездника (`flags.nazgob-personal.oneWhole`), а не на токенах. Удаление, копирование и перенос токенов на другую сцену не рвут и не дублируют связь: на любой сцене, где есть оба токена, они снова склеиваются, а токен скакуна получает изображение пары. Общие хиты действуют, даже если токенов на сцене нет.

### Как это устроено

- Вся механика — в [scripts/one-whole-v0.2.0.js](scripts/one-whole-v0.2.0.js). Модуль и тестовый макрос используют один и тот же код.
- Пишет в документы только активный ГМ, все записи идут через одну очередь. Игроки просят ГМ о посадке и спешивании через запрос `CONFIG.queries`.
- Изменения хитов собираются из хука `updateActor` как дельты относительно `options.dnd5e.hp`, сводятся в пачку и записываются обоим.
- Данные о партнёре добавляет клиент, применяющий урон, через `dnd5e.preApplyDamage`: урон, который получил бы партнёр, и задет ли он тем же источником. Для Midi-QOL они готовятся ещё раньше, в `midi-qol.preTargetDamageApplication`.
- Посадка и спешивание сохраняют промежуточное состояние (`joining` / `splitting`). Если мир перезагрузить посередине, ГМ доводит операцию до конца при загрузке.
- При первом запуске ГМ удаляются эффекты и флаги версии 0.1.x. Хиты не угадываются: проверьте текущие хиты наездника и скакуна вручную.

Консоль: `NazgobMountedCombat.oneWhole.pair()`, `.unpair()`, `.resync()`, `.isPaired()`.

### Проверка макросом при выключенном модуле

[macros/one-whole-test.js](macros/one-whole-test.js) содержит ту же механику, что и модуль. Он собирается из ядра командой `node tools/build-macro.mjs`; вручную код ниже настроек не правьте.

1. Выключите модуль Nazgob Personal и перезагрузите мир.
2. Создайте макрос типа **Script**, вставьте файл и укажите в начале UUID и путь к изображению пары.
3. Запустите макрос. ГМ не нужен: достаточно прав владельца на Actor наездника и скакуна. Механика работает до перезагрузки страницы, повторный запуск переустанавливает её.

В режиме макроса в документы пишет клиент, где запущен макрос, — запускайте его только в одном окне. `DEBUG = true` выводит в консоль журнал решений (пул, диалоги, урон партнёру).

Ограничения:
- хуки есть только у этого клиента: остальные видят картинку наездника поверх скакуна;
- пока этот клиент закрыт, хиты пары не синхронизируются;
- если урон врага применяет клиент ГМа без механики, урон партнёру с его модификаторами считается по броскам урона из последнего чат-сообщения атакующего (Midi передаёт атакующего и множитель спасброска в опциях обновления);
- для урона, применённого кнопками чат-карты dnd5e на чужом клиенте, учитывается только урон цели.

## Медальон затягивающихся ран

Если у Actor экипирован предмет с точным названием `Медальон затягивающихся ран`, модуль обрабатывает штатный бросок Кости хитов через hooks D&D5e.

- расход Кости хитов остаётся штатным;
- чат-карта и штатный Hit Die workflow не заменяются;
- `flags.midi-qol.grants.max.damage.heal = true` дополнительно поддерживается для **Костей хитов**: перед вычислением броска каждая DiceTerm получает минимум, равный числу её граней (`d10 → d10min10`, `d4 → d4min4`);
- фиксированные бонусы при максимизации не меняются: `1d10 + 3 → 10 + 3`;
- если экипирован медальон, затем удваивается **весь итог броска Кости хитов**, включая модификатор Телосложения и другие модификаторы, уже вошедшие в итог;
- лечение не может поднять текущие HP выше `effectiveMax`.

Пример для `1d10 + 3`:

```text
Обычный результат 4+3 = 7                 → 7 HP
Только медальон                           → 14 HP
Только max.damage.heal: 10+3 = 13         → 13 HP
Оба эффекта: (10+3) × 2                   → 26 HP
```

### Max-heal и «Одно целое»

Midi-QOL штатно проверяет `flags.midi-qol.grants.max.damage.heal` только по первой цели общего healing roll. Для активной верховой пары модуль исправляет смешанный случай, когда одновременно лечатся всадник и скакун, но max-heal есть только у одного из них.

Например, если `1d4` выпало `2`, а max-heal есть только у всадника:

```text
Только всадник → 4 HP общего пула
Только скакун  → 2 HP общего пула
Оба сразу      → 4 + 2 = 6 HP общего пула
```

Порядок выбора всадника и скакуна не влияет на результат.

Служебные Midi-QOL hooks этой механики не возвращают `false`: это важно, потому что `midi-qol.preDamageRoll` трактует `false` как прямой запрет броска урона/лечения.

Для Midi-QOL v13 итог обычного общего healing roll захватывается на актуальном hook `midi-qol.DamageRollComplete`. Модуль также временно переставляет немаксимизируемую цель первой и в `workflow.targets`, и в `workflow.hitTargets`, потому что Midi-QOL проверяет `hitTargets.first()` раньше `targets.first()`. После формирования броска исходный порядок обоих наборов восстанавливается.

## Досягаемость и ауры верхом

Пока пара объединена и оба токена на одной сцене:

- все рукопашные атаки всадника `mwak` и `msak` проверяют досягаемость также от полного 2x2 footprint скакуна через штатный `rangeOverride.attack` Midi-QOL;
- токен всадника остаётся 1x1 и отдельной целью;
- ауры Aura Effects 1.5.2 остаются эффектами Actor всадника, но дальность рассчитывается от полного 2x2 footprint скакуна;
- при спешивании и досягаемость, и геометрия аур возвращаются к обычному токену всадника.

Для досягаемости используется штатный `rangeOverride.attack` Midi-QOL. Для Aura Effects модуль использует его собственные функции расчёта дистанции и применения/снятия дочерних эффектов; размер токена всадника физически не меняется.


## Верховое оружие

Автоматизация больше не зависит от названий предметов. Источником истины являются свойства оружия из модуля Ребреи:

```text
Верховой бой: system.properties.has("lchMounted")
Наскок:      system.properties.has("lchDash") + flags["rebreya-main"].lichWeaponPropertyValues.dashDice
```

Кости наскока, введённые в листе по-русски (`1к2`), переводятся в `1d2`. Ограничения на вид атаки нет: свойства работают для любой атаки оружием (`mwak`, `rwak` и огнестрельной `fwak` ребреи) — «Верховой бой» есть, например, у Лука всадника и Драгуна.

Свойства работают независимо друг от друга: оружие может иметь только `Верховой бой`, только `Наскок` или оба свойства одновременно. Новые предметы начинают работать автоматически, если эти данные настроены в Ребрее.

### Верховой бой

При успешном попадании оружием со свойством `lchMounted` модуль проверяет физическую пару, созданную этой автоматизацией. Если атакующий является всадником в паре, а размер цели меньше размера его скакуна, к урону добавляется `+2`.

### Наскок

Если `dashDice` содержит формулу (например, `2d2`, `3d2` или другую), она используется как дополнительный урон Наскока. Наскок учитывается только во время активного боя. Модуль отслеживает последний непрерывный прямой отрезок движения текущего хода:

- наездник без скакуна использует собственное движение;
- если персонаж верхом, движение скакуна считается движением всадника;
- последовательные прямые перемещения в одном направлении объединяются, поэтому `5 + 5 футов` считаются как 10 футов;
- после поворота отсчёт прямого отрезка начинается заново;
- перед попаданием конец отрезка должен быть ближе к текущей цели, чем его начало;
- нужно пройти по такому отрезку минимум 10 футов;
- Наскок срабатывает один раз за текущий ход и расходуется только при успешном попадании, когда бонус реально добавлен.

Бонус добавляется через `workflow.setBonusDamageRolls`, не изменяя базовую формулу оружия. Тип урона наследуется от основного урона предмета.

## Анимации огнестрела

Код — [scripts/firearm-animations-v0.2.0.js](scripts/firearm-animations-v0.2.0.js). Заменяет on-use макросы «Выстрел DIME» и «Перезарядить DIME»: слои и числа взяты из них. Нужны Sequencer, JB2A и PSFX.

Всё берётся из данных Ребреи, названия предметов не разбираются:

| Что | Откуда |
|---|---|
| огнестрел ли это | `system.type.value` = `firearmPrimitive` / `firearmAdvanced` или флаг `firearmClass` (как `isFirearmItem` ребреи) |
| тип оружия | `flags.rebreya-main.gearId` — id предмета в `data/gear.json` ребреи |
| осечка | ребрея бросает к20 в `dnd5e.postRollAttack` и ставит `flags.rebreya-main.firearmJammed` |
| перезарядка | результат метода ребреи `reloadFirearm`, вид — из свойства «Перезарядка» |

Вид перезарядки берётся из свойства «Перезарядка» оружия в ребрее (`lichWeaponPropertyValues.reload`): «Смена магазина» → `magazine`, «Перезарядка» → `single`, «Безмагазинное» → `breechless`.

Профили (`FIREARM_TYPES`, ключ — gearId):

| Оружие | Выстрел | После выстрела | Перезарядка |
|---|---|---|---|
| Револьвер (`revol-ver`), Карабин (`karabin`) | звук PSFX, вспышка и дым у дула, пуля, попадание | — | смена магазина: `reload-rifle.mp3` |
| Винтовка (`vintovka`) | то же | затвор с гильзой через случайные 0,25–0,6 с | смена магазина: `reload-rifle.mp3` |
| Тяжёлая винтовка (`tyazhelaya-vintovka`) | то же, но звук `shot-heavy-SR.wav` | затвор с гильзой через случайные 0,25–0,6 с | смена магазина: `reload-rifle.mp3` |
| Аркебуза (`arkebuza`), Мушкет (`mushket`) — примитивное | глухой `musket-shot.wav`, вспышка, дым, пуля, попадание и облако дыма на стрелке (тает за ~2 с) | — | без анимации |

Клин (осечка ребреи) играется после выстрела: звук `jam.ogg` и маленький дымок у дула; затвор после такого выстрела не передёргивается. Очистка затвора анимации не имеет. Остальной огнестрел ребреи (Мушкетон, Драгун, пистолеты и т. д.) анимаций не получает.

Все звуки лежат в `assets/audio/sound/item sound/`; другие файлы можно указать в `SHOT_OVERRIDES`.

Перезарядку ребрея выполняет сама и отменяет использование активности, поэтому Midi-хуков у неё нет. Модуль оборачивает метод `reloadFirearm` её сервиса атак (`game.rebreyaMain.combatAttackService`) и при снятии возвращает его как был. Анимация — только если ребрея реально зарядила хотя бы один патрон.

Анимацию запускает клиент, который стреляет или перезаряжает; остальные видят её через Sequencer. Правки поверх профиля сливаются по ключам, `null` выключает слой.

Проверка без атаки: `game.modules.get("nazgob-personal").api.firearms.play("vintovka", token, [...game.user.targets])`, `.playReload("vintovka", token, "magazine")`.

### Проверка макросами при выключенном модуле

Два макроса собираются из того же ядра командой `node tools/build-macro.mjs`; оба в обёртке `(async () => { … })()`, так что их можно и запускать как Script-макрос, и вставлять в консоль F12. Перед проверкой уберите с оружия on-use макросы «Выстрел DIME» и «Перезарядить DIME», иначе анимации будут двойными.

- [macros/firearms-install.js](macros/firearms-install.js) — ставит всё. В начале: `DEBUG` (журнал решений в консоли) и `SHOT_OVERRIDES` — правки профилей по gearId, например `arkebuza: { shot: { smoke: null } }`. Повторный запуск переустанавливает с новыми правками. Если модуль включён вместе с флажком «Анимации огнестрела», макрос откажется ставить второй комплект.
- [macros/firearms-uninstall.js](macros/firearms-uninstall.js) — снимает всё без перезагрузки.

Правки можно менять и на лету из консоли: `NazgobFirearms.overrides.arkebuza = { shot: { sound: { volume: 0.5 } } }`.
